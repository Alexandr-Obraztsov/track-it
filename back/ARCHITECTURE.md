# Архитектура Backend

## Обзор

Backend построен на Express.js с TypeScript, использует PostgreSQL через TypeORM и интегрирован с Telegram Bot API и Google Gemini AI.

## Основные компоненты

### 1. Routes (API Endpoints)

Все API endpoints находятся в `src/routes/`:

- **auth.ts** - Аутентификация через Telegram WebApp
- **users.ts** - Управление пользователями
- **chats.ts** - Управление чатами
- **tasks.ts** - CRUD операции с задачами
- **comments.ts** - Комментарии к задачам
- **labels.ts** - Метки для задач
- **roles.ts** - Роли пользователей
- **gemini.ts** - AI обработка текста/аудио
- **notifications.ts** - Настройки уведомлений

### 2. Services (Бизнес-логика)

- **userManager.ts** - Управление пользователями и чатами
- **geminiService.ts** - Интеграция с Google Gemini AI
- **messageProcessor.ts** - Обработка сообщений Telegram
- **task-service/** - Логика работы с задачами
- **notificationService.ts** - Отправка уведомлений
- **notificationScheduler.ts** - Планировщик уведомлений (cron)
- **taskHistoryService.ts** - История изменений задач

### 3. Entities (База данных)

TypeORM сущности в `src/entities/`:

- **User** - Пользователи
- **Chat** - Чаты/группы
- **Task** - Задачи
- **TaskComment** - Комментарии
- **Label** - Метки
- **Role** - Роли
- **TaskHistory** - История изменений
- И другие связующие таблицы

### 4. Middleware

- **auth.ts** - JWT аутентификация для защищенных endpoints

### 5. Bot

- **telegramBot.ts** - Telegram бот для обработки сообщений и команд

## Поток данных

### Обработка сообщений Telegram

1. Бот получает сообщение
2. `telegramBot.ts` определяет тип сообщения
3. `messageProcessor.ts` извлекает контент (текст/аудио)
4. `geminiService.ts` обрабатывает через AI
5. `taskService` сохраняет задачи в БД
6. Бот отправляет ответ пользователю

### API запросы

1. Клиент отправляет запрос с JWT токеном
2. `auth.ts` middleware проверяет токен
3. Route обрабатывает запрос
4. Service выполняет бизнес-логику
5. Entity сохраняет/загружает данные из БД
6. Ответ возвращается клиенту

## База данных

### Схема

Используется PostgreSQL с TypeORM. Схема находится в `database/schema/`.

Основные таблицы:
- `users` - Пользователи
- `chats` - Чаты
- `tasks` - Задачи
- `task_comments` - Комментарии
- `labels` - Метки
- `task_history` - История изменений (автоматически через триггеры)

### Миграции

TypeORM синхронизация схемы (в development):
```typescript
await AppDataSource.synchronize(false);
```

## Безопасность

1. **JWT токены** - для аутентификации API
2. **Telegram InitData** - валидация через `@tma.js/init-data-node`
3. **Helmet** - защита HTTP заголовков
4. **CORS** - настройка разрешенных источников
5. **Валидация** - проверка всех входных данных

## Логирование

Используется централизованный логгер (`src/utils/logger.ts`):
- ERROR - только ошибки
- WARN - предупреждения
- INFO - важная информация
- DEBUG - отладочная информация

Уровень логирования настраивается через `LOG_LEVEL` в `.env`.

## Уведомления

### Планировщик

`notificationScheduler.ts` использует `node-cron` для:
- Проверки дедлайнов каждую минуту
- Отправки ежедневных отчетов в заданное время

### Типы уведомлений

1. **Напоминания о дедлайнах** - за N часов до дедлайна
2. **Ежедневные отчеты** - список задач "в работе"

## AI Интеграция

### Gemini AI

Используется Google Gemini 2.5 Flash для:
- Извлечения задач из текста
- Обработки голосовых сообщений
- Умного обновления существующих задач
- Создания меток для задач

### Промпты

Промпты находятся в `configs/geminiPrompts.ts`:
- `extractGroupTasks` - для групповых задач
- `extractPersonalTasks` - для личных задач

## Тестирование

Тесты находятся в `src/__tests__/`:
- Unit тесты для services
- Integration тесты для routes
- E2E тесты для критических сценариев

Запуск: `pnpm test`

## Развертывание

1. Установить зависимости: `pnpm install`
2. Настроить `.env`
3. Собрать проект: `pnpm build`
4. Запустить: `pnpm start`

## Масштабирование

Для масштабирования можно:
- Использовать Redis для кеширования
- Добавить очереди (Bull/BullMQ) для фоновых задач
- Разделить на микросервисы при необходимости
- Использовать connection pooling для БД
